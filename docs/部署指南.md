# 浅焦映像 · 部署指南

> 目标读者：维护者 / 运维。三个入口：
> **一键部署** → 第一节｜**手动部署**（控制台操作）→ 第二节｜**网站版** → 第四节
> 云开发资源全景：**31 个云函数**（30 业务 + 1 初始化）、**11 个 ai_studio_\* 集合**、云存储 `ai-studio/` 前缀，环境配置同源于 `cloudbaserc.json`。

---

## 一、一键部署（推荐，约 10 分钟）

### 1.1 前置准备（一次性，5 分钟）

```bash
# ① 安装 CloudBase CLI（Node.js 14+）
npm install -g @cloudbase/cli

# ② 登录（浏览器扫码授权腾讯云账号）
tcb login

# ③ 确认环境 ID：cloudbaserc.json 的 envId 字段
#    当前值 cloud1-9gv5zn35c8ca8869-00c771e2；换环境时改这里 + app.js 的 env
```

### 1.2 填好密钥再部署（重要）

编辑 `cloudbaserc.json`，把两个空占位填上（部署会把这些值写成云函数环境变量）：

| 环境变量 | 影响的函数 | 生成方式 | 不填的后果 |
|---|---|---|---|
| `AI_STUDIO_ADMIN_PASSWORD` | 12 个 admin*/dispatch/export 函数 | 自定 8 位以上口令 | **管理后台完全无法登录**（安全兜底） |
| `AI_STUDIO_OPEN_API_KEYS` | photomuseOpenApi | `openssl rand -hex 16` | 网站版/第三方接入全部拒绝 |
| `AI_STUDIO_ADMIN_OPENIDS` | 同口令组 | 你的微信 OPENID（已预填） | 管理后台无法登录 |

生图/视觉模型的 API Key **不在配置文件里**，部署后在小程序管理后台"模型设置"面板在线配置（只存数据库，任何接口不回传）。

### 1.3 一键执行

```bash
npm run deploy
```

脚本（`scripts/deploy.js`）自动完成四步：

1. **登录检查**——未登录会提示 `tcb login`
2. **批量部署 30 个云函数**——超时/内存/环境变量全部读 `cludbaserc.json`（含三个特殊配置：`generateAIStudioImage` 120s、`analyzeAIStudioPhoto` 40s、`exportAIStudioPrintFile` 60s/512MB），逐个显示 ✓/✗
3. **自动建 11 个数据库集合**——调用 `initAIStudioCollections`（幂等，重复执行安全；已存在的集合自动跳过）
4. **部署后自检**——函数成功数统计 + 空口令/空 Key 预警 + 下一步提示

常用变体：

```bash
npm run deploy:dry                                        # 干跑：只打印 30 个函数的部署计划与配置，不执行
npm run deploy -- --only=createAIStudioOrder,photomuseOpenApi   # 只更新指定函数（日常改代码后热更）
npm run deploy -- --skip-invoke                           # 跳过建集合（集合已建好时）
```

> 没装全局 CLI 也能跑：脚本会自动用 `npx -y @cloudbase/cli` 拉起（首次慢 1-2 分钟）。

### 1.4 部署后验证（2 分钟）

```bash
tcb fn invoke getAIStudioBusinessConfig -e <envId>
# 期望输出含 "baseThemePrice":69.9 —— 说明函数+集合默认值链路通了

tcb fn invoke initAIStudioCollections -e <envId>
# 期望 "existedCount":11 —— 集合全部就绪
```

小程序侧：微信开发者工具打开 `F:\PhotoMuse` → 编译 → 首页能加载套餐与价格（走了 getAIStudioBusinessConfig/listMyAIStudioOrders）即通。完整真机回归路径见 [上线检查清单.md](./上线检查清单.md)。

## 二、证件照引擎 HivisionIDPhotos（自部署，可选但强烈推荐）

> 开源 Apache-2.0（[Zeyi-Lin/HivisionIDPhotos](https://github.com/Zeyi-Lin/HivisionIDPhotos)）：抠图→换底→按规格出照→六寸排版，**纯 CPU 即可**（0.2 秒/张、内存约 410MB）。部署后 ¥3.9 证件照从"人工修图"升级为**全自动秒级出图**。

### 2.1 服务器部署（任意一台 2 核 2G 的 Linux）

```bash
# 方式一：Docker（推荐）
docker run -d --name hivision-idphotos --restart always \
  -p 8080:8080 linzeyi/hivisionidphotos
# （镜像若不可用，用方式二源码部署）

# 方式二：源码（Python 3.9+）
git clone https://github.com/Zeyi-Lin/HivisionIDPhotos.git
cd HivisionIDPhotos
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python deploy_api.py   # 默认监听 0.0.0.0:8080

# 验证
curl -X POST http://127.0.0.1:8080/idphoto -F "input_image=@任意照片.jpg" \
  -F "height=413" -F "width=295" -F "hd=true" -F "dpi=300"
# 期望返回 {"status":true,"image_base64_hd":"..."}
```

### 2.2 安全（重要）

引擎本身无鉴权，必须做网络隔离，三选一：
- **防火墙白名单**：8080 端口仅放行腾讯云函数出口 IP（云开发函数固定出口可在控制台查看）+ 你的管理机
- **内网穿透/frp 只绑云函数可达地址**，不暴露公网
- 前面挂一层 nginx 加 Basic Auth 并配 HTTPS（此时管理后台里填 https 地址）

### 2.3 接入浅焦映像（零代码）

小程序 → 管理后台 → 模型设置 → **证件照引擎（HivisionIDPhotos）**：开启 + 填 `http://服务器IP:8080` → 保存。
之后订单管理里证件照订单卡会出现「AI 证件照」按钮：一键调 云函数 → 引擎三步（抠图/换底/排版）→ 成品与排版图自动入库（`generated/idphoto-*.jpg` + `layout-*.jpg`），预览满意后点「上传交付」即完成，全程 10-30 秒。
规格与底色已内置国标：一寸/小一寸/二寸/小二寸/五寸/六寸（300DPI 像素）× 白/蓝/红/灰/深蓝标准色（用户下单时选择，引擎按订单参数出图）。

## 三、写真生图 API（OpenAI 兼容，按厂商对照表任选）

模型设置 → **AI 生图接口（写真）**：provider 固定 `openai_compatible`，填完整 images/generations 地址 + Key + 模型名。已验证可接的厂商对照：

| 厂商/模型 | apiUrl（完整地址） | model 示例 | 备注 |
|---|---|---|---|
| 智谱 CogView | `https://open.bigmodel.cn/api/paas/v4/images/generations` | `cogview-4` | 国内直连快，你有现成 Key |
| OpenAI gpt-image-1 | `https://api.openai.com/v1/images/generations` | `gpt-image-1` | 返回 b64，我们已兼容；需海外网络 |
| xAI Grok 图像 | `https://api.x.ai/v1/images/generations` | `grok-2-image` | 写实人像质量好 |
| Nano Banana（Gemini） | 经 OpenAI 兼容网关（自建 one-api/new-api 转发）后填网关地址 | 按网关配置 | 原生为 Gemini 协议，经网关转成 images API 即可接入 |
| 任意其他 | 任何兼容 `POST {url}` + `Authorization: Bearer` + `{model,prompt,n,size}` 的服务 | — | 响应支持 `data[0].url` 或 `data[0].b64_json` 均可 |

> 视觉分析（AI 帮我选主题）是另一个场景 `photo_analysis`（chat/completions + 视觉模型如 `glm-4v-plus`），与生图互不影响。

## 四、手动部署（无 CLI 时的替代，约 40 分钟）

1. 微信开发者工具 → 云开发 → 云函数 → 右键 `cloudfunctions/` 下每个目录 → **上传并部署：云端安装依赖**（30 个；`exportAIStudioPrintFile` 会额外安装 jpeg-js/pngjs）
2. 三个函数在控制台改配置：`generateAIStudioImage` 超时 120s；`analyzeAIStudioPhoto` 超时 40s；`exportAIStudioPrintFile` 超时 60s + 内存 512MB
3. 数据库 → 新建 11 个集合（清单见 `cloudfunctions/initAIStudioCollections/index.js` 顶部注释；或先部署该函数再在控制台"测试"运行一次）
4. 云函数 → 逐个按 `cloudbaserc.json` 的 `envVariables` 配环境变量（管理员组 12 个函数要 OPENIDS+PASSWORD，`photomuseOpenApi` 要 OPEN_API_KEYS）

## 六、网站独立版（photomuse-web/）

**方式 A：自有服务器 + nginx（主推）**

```bash
# 1) 改配置：photomuse-web/js/config.js → ENV_ID + OPEN_API_KEY（与 1.2 同一把 Key）
# 2) 上传目录到服务器
scp -r photomuse-web/* user@server:/var/www/photomuse/
# 3) nginx 配置（仓库自带示例）
cp photomuse-web/nginx.conf /etc/nginx/sites-available/photomuse && 按需改 server_name
nginx -t && nginx -s reload
# HTTPS：certbot --nginx -d your.domain.com
```

**方式 B：CloudBase 静态托管（免服务器）**

```bash
tcb hosting deploy photomuse-web -e <envId>   # 默认目录，几分钟生效，自带 CDN
```

**控制台两步开关（两种方式都要）**：
- 环境 → 身份验证 → **启用匿名登录**（Web SDK 直传云存储依赖）
- 环境 → 安全配置 → **Web 安全域名**加入你的域名（否则 SDK 调用被拒 401）
- 云存储权限：放行 `ai-studio/` 前缀匿名读写（收紧版规则见 [Web版部署指南.md](./Web版部署指南.md) 第四节）

## 七、更新与回滚

| 场景 | 操作 |
|---|---|
| 改了某几个云函数 | `npm run deploy -- --only=函数A,函数B`（10 秒级热更） |
| 改了前端小程序 | 开发者工具重新上传发布（与云部署无关） |
| 改了网站静态文件 | 重跑 scp / `tcb hosting deploy` |
| 改定价/样张/周边/收款码 | 小程序管理后台在线改（business_config 等集合），**无需重新部署** |
| 回滚云函数 | 控制台该函数 → 版本历史 → 回退；CLI 无一键回滚 |
| 回滚数据库 | 集合数据无版本化，重要配置（定价/商品目录）改动前先在后台截图或导出 JSON 备份 |

## 八、常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| `npm run deploy` 提示未登录 | CLI 凭证过期 | `tcb login` 后重跑 |
| 部署成功但管理后台进不去 | `AI_STUDIO_ADMIN_PASSWORD` 为空或 OPENIDS 不是你的微信 | 改 cloudbaserc 重跑，或控制台改环境变量 |
| 网站报 FORBIDDEN | `AI_STUDIO_OPEN_API_KEYS` 未配 / config.js 的 Key 不一致 | 1.2 配置后 `--only=photomuseOpenApi` 重部署 |
| 网站能打开但上传照片失败 | 未开匿名登录 / 安全域名 / 存储权限 | 第四节"控制台两步开关" |
| 网站上传 413 | nginx 默认 1M 限制 | `client_max_body_size 12m;`（示例 nginx.conf 已含） |
| AI 出图按钮报"生图接口未配置" | 模型设置没配 | 小程序管理后台 → 模型设置 → 填 OpenAI 兼容地址+Key（如智谱 images/generations + cogview-4）；视觉分析配 photo_analysis 场景（glm-4v 类） |
| 生图超时 | 所配厂商接口慢 | 已设 120s；仍超时换更快的厂商/模型 |
| AI 证件照报 CONFIG_MISSING | 证件照引擎未配置 | 部署指南第二节：部署 HivisionIDPhotos 后在模型设置填地址 |
| AI 证件照报 GENERATION_FAILED | 引擎不可达/防火墙拦截 | 服务器 curl 自测通后，检查云函数出口 IP 白名单 |
| 导出制作稿报 DECODE_FAIL | 成片是 jpeg/png 之外的格式 | 用 jpg/png 成片（生图接口默认输出即 jpg） |

## 九、部署架构速览

```
npm run deploy（scripts/deploy.js）
   │  读 cloudbaserc.json（唯一配置源：31 函数 × 超时/内存/环境变量）
   ├─→ tcb fn deploy ×30 ──→ 云函数（业务 29 + init 1）
   ├─→ tcb fn invoke initAIStudioCollections ──→ 自动建 11 个集合（幂等）
   └─→ 部署后自检（成功统计 + 空口令预警）

小程序（开发者工具上传） ─┐
网站 photomuse-web（nginx/托管）─┼─→ 同一云开发环境：函数 + 集合 + 存储
第三方（API Key 网关）───────────┘
```

改动配置的唯一入口是 `cloudbaserc.json` —— 改完重跑 `npm run deploy` 即全量生效。

## 十、密钥管理（本地文件，不入公开仓库）

**位置**：项目根目录 `.deploy-secrets.json`（已 gitignore，模板见 `.deploy-secrets.example.json`）

```json
{
  "AI_STUDIO_OPEN_API_KEYS": "网站/第三方接入凭证",
  "AI_STUDIO_ADMIN_PASSWORD": "管理后台口令"
}
```

**机制**：`npm run deploy` 会自动用文件里的值替换 cloudbaserc.json 中同名环境变量的空占位——仓库里永远只有空占位，真实密钥只存在你本机。

**修改/轮换步骤**（以换开放 API Key 为例）：
1. 生成新 Key：`openssl rand -hex 16`
2. 改两处：`.deploy-secrets.json` 的 `AI_STUDIO_OPEN_API_KEYS` + 服务器 `/var/www/pm/js/config.js` 的 `OPEN_API_KEY`
3. 热更云函数：`npm run deploy -- --only=photomuseOpenApi`（10 秒）
4. 网站刷新即生效（无缓存）

**改管理口令**：只改 `.deploy-secrets.json` 的 `AI_STUDIO_ADMIN_PASSWORD`，然后 `npm run deploy -- --only=adminListAIStudioOrders,adminReviewAIStudioOrder,adminDeliverAIStudioOrder,adminSetAIStudioPaymentQR,adminMarkAIStudioOrderPaid,adminUploadAIStudioGridPreview,adminUpsertAIStudioRuntimeConfig,adminUpsertAIStudioBusinessConfig,adminUpsertAIStudioSamples,adminUpdateMerchProduction,exportAIStudioPrintFile,dispatchAIStudioJob`（或直接全量 `npm run deploy`）。

**当前已生成的密钥**（2026-08-22，记录在你本机 `.deploy-secrets.json`，遗失可随时重新生成轮换）。
