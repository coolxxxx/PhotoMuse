# 南鸢写真 Skill 吸收评估

> 来源：[@nanyuan0412 推文](https://x.com/nanyuan0412/status/2092610535225454825) → 开源仓库 [nuyoah-ai-works/nuyoah-xiezhen-prompt](https://github.com/nuyoah-ai-works/nuyoah-xiezhen-prompt)（MIT License, v1.1.0）
> 评估日期：2026-08-27 · 结论：**建议吸收 5 项方法论，融入我们的三阶段生成器指令（docs/系统指令：多角度专业摄影作品集生成器（终极版）.md）与选片/返修流程**

## 一、该 Skill 是什么

一套「摄影方案复拍」提示词工程方法论：看懂一组参考图 → 提取共同视觉 DNA（妆造/色彩/布光/质感）→ 换人物按同一企划重拍新分镜，并在生图环节做质量检查与追溯。与我们「参考图 0 → 3×5 网格 → 选格出高清」的三阶段流水线高度同构，但它的强项在我们薄弱的细节层。

## 二、建议吸收（按收益排序）

### 1. 光照拓扑重建 → 阶段三高清重绘（收益最大）
- **它的规则**：机位变化不能带着光源一起旋转。光源—遮挡—落点—反射—曝光固定在世界坐标；新机位先重建受光关系再编译 Prompt，并产出至少 4 条互相一致的拓扑预测（眼神光、面部亮暗侧、肩臂落点、环境反射、人物背景曝光差）。
- **我们的痛点**：cell 高清化时偶发光影漂移、高清后氛围与网格预览不一致。
- **落地方式**：在 generateAIStudioImage 的 cell 阶段 prompt 模板中追加约束段：「更换构图时保持光源方向/遮挡关系/环境反光不变，明确眼神光方向与面部亮暗侧，人物与背景明度关系与预览格一致」。

### 2. 表情因果链 → 网格 15 分镜
- **它的规则**：`现场触发 → 身体即时反射 → 五官可见变化 → 视线/手部追随`；禁用"自然、灵动、惊喜"等无因果情绪标签。
- **我们的痛点**：网格中人像笑容容易空洞雷同、"克隆感"。
- **落地方式**：为 15 个指定视角各配一个具体事件触发词（风吹发丝/伞面透光/茶杯递手/回头唤人……），写入网格生成 prompt 的分镜描述里。

### 3. 输入重置合同 → revision 返修流
- **它的规则**：每轮返修必须从【原始参考图】重新编译完整 Prompt，上一轮生成图只用于诊断，禁止"在旧 Prompt 末尾加补丁式修图指令"。
- **落地方式**：写进 revision 状态的处理 SOP 与后续自动化返修的 prompt 组装逻辑（当前返修是人工处理，先把规则文档化）。

### 4. 参考图职责分离 → 用户多图上传场景
- **它的规则**：区分「人物身份图」（只回答她是谁，锁五官辨识度）与「写真方案参考图」（只回答这套怎么拍，不承担身份）；用户给多张图且未说明时只问一次用途。
- **落地方式**：uploadAIStudioPhoto 支持最多 3 张——文档约定：第一张默认身份锚点；管理后台审核时若发现风格参考误传，人工标注。中期可在 analyzeAIStudioPhoto 的视觉分析里让模型自判图的职责。

### 5. 质感条款 → cell 高清阶段
- **皮肤纹理≠皮肤反射**：近景控制底妆反射和高光范围；
- **去商业抛光检查**：若原方案依赖欠曝/失焦/抓拍感，防止模型自行补"连续暖色轮廓光+英雄式构图"。我们的样张和成片偏商业亮调，这条主要防"过头精致"，作为可选条款。

## 三、暂不吸收

| 项 | 原因 |
|---|---|
| Eagle 归档 / 署名控制 | CLI 个人工作流场景，与云端流水线无关 |
| 多模式入口判断（拆解/抽卡/变体…） | 我们的业务路径固定：下单→三阶段→交付 |
| 逐字 Prompt 文本 | MIT 允许复制，但仅借鉴方法论并自行措辞，注明出处即可 |
